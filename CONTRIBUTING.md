# Contribuer

Merci de contribuer à Daily Reporting. Les modifications doivent préserver la confidentialité des données et l'isolation des équipes.

## Flux de travail

1. Créer une branche depuis `main`, par exemple `feature/nom-court` ou `fix/nom-court`.
2. Garder les changements ciblés et ajouter ou adapter les tests concernés.
3. Exécuter les validations frontend et backend décrites dans le [README](README.md#tests-et-compilation).
4. Ouvrir une pull request vers `main` avec le contexte, le comportement attendu et les validations exécutées.
5. Demander une revue avant fusion ; ne pas pousser directement sur `main`, sauf autorisation explicite des mainteneurs.

## Qualité attendue

- Ne pas inclure de secrets, données réelles d'employés ou exports de production.
- Respecter les conventions déjà présentes dans chaque module.
- Signaler clairement les changements de configuration, de schéma ou de comportement.
- Mettre à jour la documentation liée à tout changement d'usage ou de configuration.
